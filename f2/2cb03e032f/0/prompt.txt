## Initial plan
Do not merge openfort into a new develop branch. The cleanest and safest route is to preserve
   commit hashes by moving branch refs only:

   1. Keep openfort alive, at least temporarily.
   2. Rename/archive current develop as develop-particle.
   3. Point the new develop branch directly at the current openfort commit (a6376ab locally /
      origin/openfort).
   4. Update GitHub default branch from develop to the newly promoted develop if needed.
   5. Preserve and push Entire checkpoint branches (entire/checkpoints/v1 and/or dedicated *-entire
      repo refs) unchanged.

   Why this is better than merging

   Current graph check shows develop...openfort is 0 95, meaning openfort already contains current
   develop and is 95 commits ahead. A merge would add an unnecessary merge commit and may confuse
   tooling by creating a new top commit that is not itself one of the session-linked commits.

   Entire docs/README indicate sessions are indexed alongside commits, active branch commits stay
   clean, and metadata is stored separately on entire/checkpoints/v1; they also support entire 
   session resume <branch>. That suggests the important invariant is preserving commit SHAs and
   Entire checkpoint refs, not preserving the old branch name exclusively.

   sh

     git push origin origin/develop:refs/heads/develop-particle

     # Keep openfort for a grace period; do not delete yet.
     # Verify Entire metadata refs still exist locally/remotely:
     git branch -a | grep 'entire'
     git ls-remote origin 'refs/heads/entire/*'
