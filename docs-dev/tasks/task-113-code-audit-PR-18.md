## TL;DR

**Do not merge as-is.** The PR is built against pre-v1.1.0 `develop`, when auth was Particle. It reintroduces `@particle-network/connectkit` (a dependency that no longer exists in `package.json`) and rewrites `src/components/header.tsx` against an obsolete version of the file that has since been entirely replaced by the Openfort-based header. But the wiring layer (Jotai atoms, `useUser` hook, header changes) has to be rebuilt on top of `useAuthSession()` / `backendUser` rather than Particle. The only purely additive parts (`globals.css` token, `form-input.tsx` props, the setting components themselves) can be cherry-picked once the Particle layer is removed.

## Critical blockers

### 1. Reintroduces Particle as a dependency

`src/hooks/useUser.ts` and the diff for `src/components/header.tsx` both import from `@particle-network/connectkit`:

```ts
import { useAccount, useParticleAuth } from '@particle-network/connectkit';
```

Particle was removed in v1.1.0 (see `docs-dev/release-notes/v1.1.0-openfort-branch-becomes-develop.md`). `package.json` only ships `@openfort/react`. Merging this PR will fail at install or at type-check.

### 2. `header.tsx` was rewritten and the PR is unaware of it

Current `src/components/header.tsx:1-42` no longer renders the greeting "Hi {userName} - {role}" at all. Recent commits:

- `cc5c0bf feat(account): task 105 avatar dropdown menu and wallet row on account page` — introduced `AvatarMenu`
- `8fd3ace feat(header): remove greeting and email from page header` — removed the greeting that the PR was trying to refactor

The PR's central refactor — extracting the greeting/role logic into `useUser` and `userAtoms` — is solving a problem that no longer exists in this surface. The avatar/display name logic has already moved to `src/components/header/avatar-menu.tsx`, which sources display name and email directly from `useAuthSession()`'s `backendUser` and `openfortUser`.

### 3. Role storage layer is obsolete

`userAtoms.ts` writes/reads `localStorage['infrafund_user_role']`. That key is not used anywhere in current `develop` — `grep -rn "infrafund_user_role" src/` returns nothing. Role and type now flow from the backend in `BackendMeResponse` (`src/lib/backend-auth-client.ts:60-73`):

```ts
export interface BackendMeResponse {
  user_id: string;
  openfort_user_id: string;
  email: string | null;
  first_name: string | null;
  last_name: string | null;
  company_name: string | null;
  phone_number: string | null;
  type: string;
  role: string;            // ← authoritative source of role
  status: string;
  kyc_verified: boolean;
  kyb_verified: boolean;
}
```

`useAuthSession()` exposes this as `backendUser`. The settings page should consume that, not reintroduce a localStorage role.

### 4. `press-section.tsx` hunk no longer applies

PR changes:

```diff
-import { FileUploadWithPreview } from '@/components/ui/file-upload-with-preview';
+// import { FileUploadWithPreview } from '@/components/ui/file-upload-with-preview';
```

Current `develop` already removed that import (the JSX block using it was commented out earlier). The hunk will conflict and is unnecessary — drop it from the rebased PR.

## Non-blocking issues

### 5. `form-input.tsx` — soft conflict, both sides want to land

Current `develop` has an `invalid?: boolean` prop with `aria-invalid` + red border. The PR adds `prefix?: string` and `disabled?: boolean`. Both sets are useful and orthogonal. On rebase, merge them rather than overwriting.

### 6. Directory name `profile-detail.tsx/`

The four child components live under `src/components/setting/profile-detail.tsx/`. Naming a directory with a `.tsx` suffix is legal but confusing — every editor and tool treats `.tsx` as a file extension. Suggest renaming to `profile-detail/` before merge.

### 7. Missing newlines at EOF in 7 added files

`header.tsx`, `userAtoms.ts`, `main-setting.tsx`, all four `profile-detail.tsx/*.tsx`, `useUser.ts`, `form-input.tsx`. Prettier will flag.

### 8. `PersonalInformation` splits `userName` on space

```tsx
const names = userName.trim().split(' ');
firstName: names[0] || '',
lastName: names.length > 1 ? names.slice(1).join(' ') : '',
```

Lossy and unnecessary — `backendUser.first_name` and `backendUser.last_name` are already separate fields. After the rewrite, drop the `useUser`/atom layer here and read directly from `useAuthSession()`.

### 9. UI scaffolding without persistence

`InvestmentPreferences`, `PersonalInformation`, and `RoleAccess` keep state in `useState` only — no backend round-trip on save. `RoleAccess` also hardcodes "Investor Role Badge / Token ID: 101", "GB123456789", "Accredited Investor". This matches the broader pattern flagged in `docs-dev/tasks/task-112-code-audit.md` §4.2 — fine for visual scaffolding, but the Save / Discard buttons in `profile-detail.tsx` need a follow-up task to wire to `/api/v1/account/me` (or equivalent).

### 10. Route name `/setting` (singular)

App convention is mixed but most multi-feature routes are plural-ish (`/explore-projects`, `/digital-assets`, `/investment-portal`). `/settings` would be more conventional. Worth changing while the route is brand-new.

### 11. `globals.css` token placement

`--color-heading-text: #f3f4f6;` is added between `--color-primary-300` and `--color-primary-hover` inside `@theme`. It's unrelated to primary, should sit with the gray scale — minor.
