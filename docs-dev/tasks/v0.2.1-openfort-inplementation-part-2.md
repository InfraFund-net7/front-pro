# v0.2.1 Openfort Implementation Part 2

**Date:** 2026-03-27
**Status:** Approved plan
**Predecessor:** `docs-dev/audit-review/v0.2.0-openfort-integration-review-1.md`

## Goal

Finish the Openfort migration in `front-pro` as part of a coordinated frontend + backend move away from Particle.

## Current State

- Openfort provider wiring is structurally correct.
- `/login` uses `OpenfortButton`.
- Automatic recovery endpoint is present.
- Legacy guest header, wallet modal, and bearer-token utilities still exist and remain active in the main app.
- `backpro` already has JWT/session infrastructure, but its auth contract is still Particle-based.

## Selected Direction

- **Option B selected:** coordinated `front-pro` + `backpro` migration
- **Frontend branch of record:** `openfort`
- **Backend branch of record:** `openfort`
- **Frontend route policy:** all non-`/login` pages are treated as authenticated app pages
- **Wallet UX policy:** use Openfort stock UI/modal, remove custom wallet/login flow from the live path
- **External wallet policy for this phase:** do not depend on `AuthProvider.WALLET` / WalletConnect unless explicitly reintroduced later

## Branch Strategy

## Target Outcome

1. Users authenticate through Openfort and remain authenticated across the app.
2. Protected app routes in `front-pro` respect auth state.
3. The header and wallet entry points use Openfort state/components instead of legacy mock flows.
4. Backend API access is aligned with an Openfort-compatible backend session model.
5. The app exposes a clear sign-in / sign-out / connected-wallet experience.
6. `backpro` preserves its JWT/refresh/session architecture while replacing Particle as the identity source.

## Backend Dependency Summary

`backpro` already has:

- JWT access tokens
- refresh-token cookie flow
- auth middleware
- session / lockout logic
- tests and clean layering

But it is still provider-bound to Particle:

- login/register expect `uuid` + `token`
- auth service calls `particle.GetUserInfo(...)`
- users are keyed around `ParticleID`
- wallet creation depends on Particle user info

So the backend effort is not “build auth from scratch”; it is “swap the identity source while preserving the existing session architecture.”
