# v0.3.1 — Remove SSR from App Providers

**Date:** 2026-04-15
**Status:** Pending
**Branch:** `openfort`

## Background

The app already functions as a pure client-side application — every page and component uses `'use client'`, and all data fetching happens in the browser. The only remaining SSR surface is `AppProviders` (wagmi + Openfort) being rendered as an empty shell on the server.

In v0.3.0 a `ssr: true` flag was added to the wagmi config as a targeted fix for a hydration `setState` warning caused by `OpenfortWagmiBridge`. The preference is to eliminate the SSR surface entirely rather than papering over individual hydration issues.

## Current State

- `src/app/layout.tsx` — `RootLayout` is a server component; imports `AppProviders` as a static import, so wagmi and Openfort providers run on the server
- `src/lib/openfort-config.tsx` — `wagmiConfig` has `ssr: true` as a workaround for the hydration warning

## Goal

Prevent `AppProviders` (wagmi + Openfort + `AuthSessionProvider`) from ever running server-side. Eliminate `ssr: true` from wagmi config since it becomes unnecessary.

## Changes

### `src/app/layout.tsx`

Replace the static import with a `dynamic` import with `ssr: false`:

```ts
// BEFORE:
import { AppProviders } from '@/lib/openfort-config';

// AFTER:
import dynamic from 'next/dynamic';
const AppProviders = dynamic(
  () => import('@/lib/openfort-config').then((m) => m.AppProviders),
  { ssr: false }
);
```

### `src/lib/openfort-config.tsx`

Remove `ssr: true` from `getDefaultConfig` — no longer needed:

```ts
// BEFORE:
getDefaultConfig({
  appName: 'InfraFund',
  chains: [baseSepolia, base],
  ssr: true,
  ...
})

// AFTER:
getDefaultConfig({
  appName: 'InfraFund',
  chains: [baseSepolia, base],
  ...
})
```

## Trade-offs

- On the very first page load the browser renders a blank body for ~100ms before React mounts `AppProviders`. Since the app immediately shows a loading spinner or login screen (all guarded by `MainLayout`), this is imperceptible in practice.
- The encryption-session API route (`src/app/api/auth/encryption-session/route.ts`) is a Route Handler, not a component — it is unaffected.
- `output: 'standalone'` in `next.config.ts` is unaffected.
- No hydration warnings will be possible from wagmi or Openfort providers since they never run on the server.
