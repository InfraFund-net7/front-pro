## Concrete Frontend ↔ Backend Contract For This Phase

Use a dedicated backend session-exchange endpoint instead of reviving the old Particle login/register proxies:

- `POST /v1/auth/openfort/exchange`
  - frontend sends `Authorization: Bearer <openfort_access_token>`
  - token source is `await useUser().getAccessToken()`
  - request body is optional and should only carry app-specific profile fields that Openfort does not own
- `POST /v1/auth/refresh`
  - uses the existing backend refresh-cookie flow
- `POST /v1/auth/logout`
  - revokes backend refresh session
- `GET /v1/me`
  - returns the backend user/profile/session view for the authenticated app shell

Recommended frontend behavior:

- after Openfort login succeeds, exchange the Openfort token for an InfraFund backend session
- keep the returned backend access token in memory, not `localStorage`
- call `backpro` directly from the browser with `credentials: 'include'`
- keep only the Openfort Shield recovery route in Next.js; do not keep the old auth proxy layer alive just to preserve Particle-era paths
