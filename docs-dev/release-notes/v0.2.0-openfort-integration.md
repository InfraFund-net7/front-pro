# v0.2.0 — Openfort Integration

**Date:** 2026-03-27
**Base:** `develop` branch, built on top of `v0.1.0`

Viem. This release establishes a clean, working auth and wallet foundation for
the InfraFund frontend.

## Environment Variables

### Client-side (NEXT_PUBLIC_)

| Variable | Required | Source |
|----------|:--------:|--------|
| `NEXT_PUBLIC_OPENFORT_PUBLIC_KEY` | Yes | Openfort Dashboard or `~/.config/openfort/credentials` |
| `NEXT_PUBLIC_SHIELD_API_KEY` | Yes | `openfort embedded-wallet setup` |
| `NEXT_PUBLIC_POLICY_ID` | No | Dashboard > Policies > Fee Sponsorship |
| `NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID` | No | https://cloud.walletconnect.com |
| `NEXT_PUBLIC_API_BASE_URL` | No | Your backend API URL |

### Server-side only

| Variable | Required | Source |
|----------|:--------:|--------|
| `SHIELD_SECRET_KEY` | Yes* | `openfort embedded-wallet setup` |
| `SHIELD_ENCRYPTION_SHARE` | Yes* | `openfort embedded-wallet setup` |

*Required for automatic wallet recovery. Without these, wallets still work but
users must set up manual recovery (password or passkey).

## Setup Instructions

```bash
# 1. Install Openfort CLI
npm install -g @openfort/cli

# 2. Authenticate
openfort login

# 3. Set up backend wallet signing keys
openfort backend-wallet setup

# 4. Set up Shield (embedded wallet encryption)
openfort embedded-wallet setup

# 5. Copy keys to .env.local
cp .env.example .env.local
# Then populate with values from ~/.config/openfort/credentials
# and the Shield setup output

# 6. Run dev server
npm run dev
```

## Architecture Decisions

### Why Openfort over Particle Network

| Concern | Particle (removed) | Openfort (new) |
|---------|-------------------|----------------|
| Vendor lock-in | MPC keys on Particle's network | OpenSigner is self-hostable |
| Type safety | Standard TS hooks | Viem-native with `as const` ABI inference |
| Gas sponsorship | Separate paymaster setup | Built-in Policy Engine |
| Integration quality | Merged with security issues (PR #11) | Clean implementation from docs |
| Boilerplate | ~160 lines across 3 files + broken | ~30 lines config + `<OpenfortButton />` |

### Why keep React 18

React 19 has breaking changes. `@openfort/react` supports React 17-19, but
upgrading React major + new Openfort integration simultaneously is risky.
React 19 upgrade is deferred to a separate release.

### Why skip Docker for now

The previous team deployed via Docker Compose to self-hosted runners. We'll
deploy to Vercel once the app is working. Docker setup is retained in
`deployment/` but not actively used.

## Known Limitations

- Google OAuth requires configuring OAuth consent screen in GCP + adding
  the redirect URI in the Openfort dashboard
- Gas sponsorship requires creating a policy + sponsorship via CLI or dashboard
- The `connectwallet/` component directory still contains old static UI mockups
  that are not connected to Openfort — these can be removed in a future cleanup
