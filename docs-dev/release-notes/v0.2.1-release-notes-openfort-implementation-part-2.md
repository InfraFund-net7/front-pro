# v0.2.1 — Openfort Implementation Part 2

**Date:** 2026-03-27
**Status:** In progress
**Branches:** `front-pro/openfort`, `backpro/openfort`

---

## Summary

This phase completed the core coordinated Openfort migration work across the
frontend and backend. The remaining blocker before true end-to-end verification
is runtime configuration: required env vars, API keys, and local service setup
still need to be populated.

---

## What is done so far

### Frontend (`front-pro`)

- Added app-wide auth/session bootstrapping around Openfort + backend session exchange
- Added client-side route guarding for the authenticated app shell
- Updated `/login` to use `OpenfortButton`
- Replaced the live header wallet flow with Openfort-native UI/state
- Added direct browser → backend auth client flow using:
  - `POST /v1/auth/openfort/exchange`
  - `POST /v1/auth/refresh`
  - `POST /v1/auth/logout`
  - `GET /v1/me`
- Removed the legacy Next.js auth/BFF proxy routes and localStorage token plumbing
- Kept the Shield encryption-session route for wallet recovery

### Backend (`backpro`)

- Added Openfort session validation client and Openfort-backed auth exchange flow
- Replaced the active auth contract with:
  - `POST /v1/auth/openfort/exchange`
  - `POST /v1/auth/refresh`
  - `POST /v1/auth/logout`
  - `GET /v1/me`
  - `GET /v1/account/status`
  - `GET /v1/kyc/status`
- Switched backend identity from Particle-era assumptions to `openfort_user_id`
- Removed Particle from the active auth implementation and routing contract
- Updated deployment/config surfaces to use Openfort auth env vars
- Replaced the `sonic` JSON dependency with the Go standard library to resolve the local build blocker
