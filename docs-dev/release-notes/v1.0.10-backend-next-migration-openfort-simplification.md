# v1.0.10 Backend Next Migration: Phase 10 Completion

Phase 10 completes the Go backend retirement pass and keeps the Openfort integration lean inside the single Next.js app.

## Changes

- Confirmed active frontend and deployment wiring no longer uses `NEXT_PUBLIC_API_BASE_URL`, `API_URL`, `backpro`, `localhost:8080`, or direct old `/v1` calls.
- Kept frontend API calls same-origin under `/api/v1`.
- Reviewed the Openfort integration against the project Openfort skill, current React embedded wallet docs, and the Openfort `auth-sample` reference.
- Kept the EVM provider stack as `QueryClientProvider` → `WagmiProvider` → `OpenfortWagmiBridge` → `OpenfortProvider`.
- Preserved `connectOnLogin: false`, automatic recovery, token-verified Shield encryption sessions, and post-qualification wallet creation.
- Removed remaining Go-era server env aliases from active runtime config.
- Expanded `.env.example` with the required Next.js-owned database, session, cron, captcha, Shield, and optional SMTP variables.

## Manual test follow-up

A separate browser-based Openfort auth and wallet recovery smoke test is still required with real Openfort and Shield project keys. The automated/local checks can verify build/runtime shape, but they cannot complete hosted Openfort login, qualification, wallet creation, or recovery without valid project credentials.
