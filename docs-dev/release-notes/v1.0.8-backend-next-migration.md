# v1.0.8 Backend Next Migration

## Summary

Phase 8 removes the frontend and deployment wiring that could still point to the retiring Go backend. Frontend backend calls now always use the same-origin Next.js API surface under `/api/v1`.

## Implemented

- Updated `src/lib/backend-auth-client.ts` so every app backend request resolves to `/api/v1/...`.
- Removed `NEXT_PUBLIC_API_BASE_URL` support from the frontend API client.
- Removed obsolete `NEXT_PUBLIC_API_BASE_URL` Docker build args and environment wiring.
- Removed obsolete `API_URL` Docker Compose wiring.
- Removed Go-backend API URL wiring from the dev and production deploy workflows.
- Removed `NEXT_PUBLIC_API_BASE_URL` from `.env.example`.

## Notes

- No `getServerUrl(...)`, `src/services/apiService.ts`, or `src/utils/get-server-url.util.ts` implementation exists in the current app, so there was no proxy helper to port.
- No legacy route aliases were added because current UI call sites already go through `src/lib/backend-auth-client.ts` and resolve to `/api/v1/...`.
- Historical release notes may still mention the old Go backend URL variable for archival context, but runtime code and active deployment wiring no longer depend on it.

## Validation

- `npm run format`
- `npx tsc --noEmit`
- `npm run build`
