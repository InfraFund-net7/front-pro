**Status:** Merged

## Background

Disconnect was broken on the Vercel preview deployment after `d80ded7` (Next.js security patch). Five stacked fix attempts (`5f64d4a` → `808427c`) failed to converge: each addressed a peripheral concern (callback param stripping, modal reset, in-progress markers, switching SDK hook) while leaving the core regression in place. On localhost the same flow appeared to work, masking the root cause.

## User-visible symptoms

Both disconnect entry points were affected:

- **InfraFund avatar-menu Disconnect** (top-right avatar → Disconnect)
- **Openfort built-in modal Disconnect** (open Openfort modal → profile → Disconnect)

After clicking either:

- Browser left on a blank page with a long callback-style URL containing `openfortAuthProviderUI`, `access_token`, `user_id`.
- Reloading that page could re-trigger the 5-step auth bootstrap and log the user back in.
- On localhost, intermediate fix attempts also flashed the 5-step "Loading…" modal for ~100 ms before the page reloaded.

## Resolution

Reworked the disconnect flow in `src/components/auth/auth-session-provider.tsx` so both entry points converge on a single, deterministic exit path:

1. Strip stale Openfort OAuth callback params from the URL (`openfortAuthProviderUI`, `access_token`, `user_id`, `error`).
2. Fully `await` the Openfort logout via `useOpenfortCore().logout` (the SDK clears its storage during the awaited promise).
3. Hard-reload to `/` via `window.location.assign('/')` (or `reload()` if already on root) so `OpenfortProvider` reinitialises from a clean URL and a cleared SDK store.
4. Revoke the InfraFund backend session in parallel.
5. Use a `logoutInProgressRef` guard to prevent the bootstrap useEffect from re-firing mid-disconnect (kills the 5-step modal flash).

A second change in `vercel.json`: the `ignoreCommand` now skips every `entire/*` branch, not just `entire/checkpoints/v1`, so session-history branches no longer trigger broken Vercel deployments.

## Why this is in `docs-dev/openfort/` as well

The implementation pattern (which SDK hook to use, why soft navigation breaks Openfort logout, why the Openfort docs example is incomplete for any app that also owns its own backend session) is reusable knowledge. It now lives at `docs-dev/openfort/disconnect-logout-implementation-pattern.md` so the next engineer who hits this — or who starts a new Openfort app — can find the correct pattern without rediscovering it from scratch.
