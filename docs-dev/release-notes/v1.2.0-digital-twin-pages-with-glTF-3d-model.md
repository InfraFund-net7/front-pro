# v1.2.0 — Digital Twin Pages with glTF 3D Models

**Date:** 2026-05-12
**Status:** Draft
**Branch:** `gltf`
**Tracking doc:** `docs-dev/tasks/task-120-glTF-dashboard/task-120.1-glTF-dashboard-plan.md`

## Summary

Adds the first AI-Digital Twin project detail pages for the developer dashboard. The implementation renders wind turbine glTF/GLB assets in-browser and establishes the route and component structure that can later be connected to database-backed project, model, milestone, and telemetry records.

## User-visible changes

- Added `/projects/1/digital-twin` for **Cornwall Wind turbine Pilot #1**.
- Added `/projects/2/digital-twin` for **Cornwall Wind turbine Pilot #2**.
- Updated the two matching developer dashboard `View AI-Digital Twin` actions to link to their project detail pages.
- Project 1 shows an operational turbine model plus four generated energy metric cards:
  - past day
  - past week
  - current month
  - past month
- Project 2 shows a construction turbine model plus a milestone checklist for:
  - concrete foundation
  - tower lower sections
  - tower higher section
  - generator
  - blade 1
  - blade 2
  - blade 3

## Technical changes

- Added Three.js rendering dependencies:
  - `three`
  - `@types/three`
  - `@react-three/fiber`
  - `@react-three/drei`
- Added a reusable client-only digital twin model viewer using R3F, Drei `useGLTF`, bounds fitting, centering, lighting, and orbit controls.
- Added temporary hardwired project configuration in `src/lib/digital-twin-projects.ts` with TODO markers for future database-backed project/model records.
- Copied the supplied model assets into public model paths so Next.js can serve them to the browser.
- Added a small type cleanup in the KYC page so the project type check passes with the current Lucide icon usage.

## Model readiness notes

The current model files are good enough for visual MVP rendering, but not yet ready for robust database-driven element status overlays:

- Project 1 `Wind-turbine.glb` appears to contain one merged mesh, so individual turbine components cannot be selected or styled independently.
- Project 2 `Wind_Turbine 2.gltf` has multiple nodes/meshes, but the names are generic or duplicated and do not provide stable external IDs.
- A future provider manifest should include stable element identifiers, ideally IFC `GlobalId` or Revit `UniqueId`, before milestone/status mapping is implemented on model parts.
