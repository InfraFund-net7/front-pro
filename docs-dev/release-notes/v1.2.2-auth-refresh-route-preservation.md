# v1.2.2 — Preserve Authenticated Routes on Refresh

**Date:** 2026-05-12
**Status:** Merged
**Branch:** `develop`

## Summary

Fixes authenticated page refresh behavior after the digital twin project detail pages exposed two auth restore regressions:

- refreshing `/home` showed the full auth bootstrap progress flow again
- refreshing `/projects/1/digital-twin` restored the session but redirected to `/home` instead of staying on the project detail route

## Resolution

Updated the Openfort/app-session bootstrap flow so browser refresh behaves like session restore, not a new login:

1. Refresh-cookie restore now finalizes the InfraFund app session immediately after loading `/me`.
2. Embedded wallet reconnection is started in the background instead of blocking the page render.
3. The visible 5-step auth progress modal is only seeded for true interactive Openfort login/bootstrap paths.
4. Private-route guarding now redirects to `/` only after auth is definitively unauthenticated, preserving deep links during transient restore states.

The logout implementation pattern from v1.1.3 remains intact: custom and Openfort built-in disconnect still await `useOpenfortCore().logout`, revoke the backend session, strip callback params, and hard-reload to `/`.

## Notes

The embedded wallet iframe/bridge is runtime state and does not survive a full page refresh as a live connection. Reconnecting it is still necessary for wallet operations, but it should not block normal page rendering when the app session and profile are already restored from the backend refresh cookie.
