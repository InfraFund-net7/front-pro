# v0.3.0 — Openfort Integration Release Notes

**Date:** 2026-04-15
**Branch:** `openfort`
**Package version:** `0.2.6`

---

## Summary

This release completes the Openfort authentication and embedded wallet integration, resolves all open review items from v0.2.4, adds the Account page with self-service account deletion, and introduces a comprehensive operational configuration reference.

---

## What's New

### Account Page (`/account`)

New page accessible from the sidebar under **Account** (UserCircle icon, both `client` and `full` nav models).

- Displays profile info: name, email, role, account type, status, KYC state, organisation name
- **Danger Zone** section with a **Delete My Account** button
- Confirmation modal with Cancel / Confirm Delete
- On confirm: calls `DELETE /v1/me`, then Openfort `signOut()`, then redirects to `/`
- If the backend delete fails the error is surfaced — the sign-out does NOT proceed on failure

### Self-Service Account Deletion (`DELETE /v1/me`)

The frontend calls the new `DELETE /v1/me` backend endpoint (implemented in backpro v0.3.0). The endpoint:

- Revokes all sessions and clears the refresh cookie
- Soft-deletes the backpro user record (preserving audit trail)
- Frees the email, phone, and Openfort user ID so the same person can re-register
- Best-effort deletes the Openfort user via `DELETE /v2/users/{id}` when `INFRA_AUTH_OPENFORT_SECRET_KEY` is set

### Operational Config Reference (`config-operation/environment-variables.md`)

New file covering all deployment variables, auth provider setup steps, and CSP requirements — expanded post-review with backend team input:

- Frontend build-time and runtime variables
- Backend variables and GitHub Secrets per environment
- Docker Compose runtime injection requirements
- Google OAuth and Apple Sign-In setup steps
- Passkey setup (`RecoveryMethod.PASSKEY`)
- Openfort Dashboard Allowed Origins and OAuth redirect URL requirements per deployment target
- Content Security Policy directives (`frame-src`, `connect-src` for Openfort/Shield)
- reCAPTCHA v3 setup (Option A: reuse landing-pro keys, Option B: new credentials)

## Other Changes

- **WalletConnect init guard** — `walletConnectProjectId` is only passed to `getDefaultConfig` when the env var is set, eliminating the 30-second timeout and CORS errors when the key is absent
- **`NEXT_PUBLIC_BASE_URL` → `NEXT_PUBLIC_API_BASE_URL`** — rename in `.env.example`, all task docs, and release notes; anyone with an existing `.env.local` using the old name must rename it

## Environment Variables

### New variable required for full account deletion

| Variable | Location | Purpose |
|---|---|---|
| `INFRA_AUTH_OPENFORT_SECRET_KEY` | backpro `.env` | Enables Openfort-side user deletion on account delete. Get from Openfort Dashboard > API Keys (`sk_test_...` / `sk_live_...`). Best-effort — deletion proceeds locally if absent, with a warning logged. |

### Renamed (existing deployments)

`NEXT_PUBLIC_BASE_URL` → `NEXT_PUBLIC_API_BASE_URL` in `.env.local` / `.env.example`. The fallback has been removed.

## Testing Notes

Full new-user flow verified locally:

1. Login via Email OTP → qualification questionnaire → embedded wallet creation → `/home`
2. Navigate to `/account` → profile and account details displayed
3. Delete My Account → confirmation modal → deletion confirmed → redirect to `/`
4. Backend logs: `DELETE /v1/me 200`, Openfort user deleted (requires `INFRA_AUTH_OPENFORT_SECRET_KEY`)
5. Re-login with same credentials → qualification questionnaire shown (new user path confirmed)

## Known Limitations

- The **Wallet** button in the header shows "Not Connected" — this is the wagmi connection state, not the auth state. `connectOnLogin: false` is intentional; the embedded wallet exists but is not connected to the wagmi context. This will be addressed when on-chain transaction features are added.
- reCAPTCHA for the non-resident waitlist flow is not yet configured for local dev (skipped intentionally; backend bypasses validation when `INFRA_REST_RECAPTCHA_GOOGLE_SECRET` is empty).
- Apple Sign-In is configured in `config-operation/environment-variables.md` but not yet enabled in `openfort-config.tsx`.
