# v1.0.9 Backend Next Migration: Openfort Simplification

Phase 9 keeps the Openfort integration lean, App Router native, and independent from the retired Go backend.

## Changes

- Restored the documented EVM provider stack with `WagmiProvider`, `OpenfortWagmiBridge`, and `OpenfortProvider`.
- Kept `connectOnLogin: false` so Openfort login cannot create a wallet before InfraFund qualification succeeds.
- Switched Shield automatic recovery to a token-aware `getEncryptionSession` callback backed by the same-origin Next.js route.
- Protected `/api/auth/encryption-session` with Openfort access-token verification and user-ID matching before issuing a Shield encryption session.
- Removed the old `INFRA_AUTH_OPENFORT_PUBLISHABLE_KEY` server env alias and set deployment builds to choose the intended Base/Base Sepolia chain by environment.

## Manual test follow-up

A browser-based Openfort auth and wallet smoke test is still required with real Openfort and Shield project keys to verify the end-to-end hosted modal, qualification flow, and wallet recovery behavior.
