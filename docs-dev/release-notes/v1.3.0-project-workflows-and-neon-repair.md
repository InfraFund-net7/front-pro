# v1.3.0 — Project Workflows and Neon Repair

## Summary

This release completes the first project-management workflow milestone for Client accounts. It adds role-aware project navigation, resumable Pre-Sale project drafts, proposal document uploads, and repair migrations for Neon databases whose init migration was recorded before project tables existed.

## Highlights

- Added role/type-aware sidebar navigation for Client, Investor, Contractor, DAO, and Auditor account contexts.
- Added My Projects with draft visibility, empty states, and direct resume links for project drafts.
- Added account/project/role linking through `ProjectAccountRole`.
- Added a role badge beside the authenticated page title.
- Added the Pre-Sale Create Project flow with segmented wizard progress.
- Added draft persistence and resume support via `/create-project?projectId=...`.
- Prefilled contact information from the authenticated account profile.
- Added proposal PDF upload support through private Vercel Blob storage.
- Added structured API validation handling with red invalid field states.
- Relaxed website/social URL validation to accept bare domains and normalize them server-side.
- Updated the hardwired wind turbine digital twin asset to `Wind_Turbine_3.gltf`.
- Added resilient Prisma migrations for project role links and missing project table repairs on Neon.

## Implementation notes

- Pre-Sale is currently the only enabled crowdfunding model; other funding models remain disabled in the wizard.
- Project drafts now create an account-role link using the current account role.
- Submitted projects route to the review summary instead of restarting the wizard.
- Proposal uploads use the server-side `BLOB_READ_WRITE_TOKEN`; the token is never exposed to the browser.
- The Neon repair migration is forward-only and idempotent so clean databases no-op while stale preview databases get the missing project enums, tables, indexes, and foreign keys.
