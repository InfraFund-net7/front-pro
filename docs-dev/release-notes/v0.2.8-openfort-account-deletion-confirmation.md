# v0.2.8 — Account Deletion Confirmation UX + Redirect Fix

**Date:** 2026-04-15
**Status:** Completed
**Branch:** `openfort`

---

## Problems

### P1 — UI does not clear after deletion

After `deleteAccount()` completes, the app sets React state to `unauthenticated` but:
- The wallet address in the header persists (comes from wagmi state, unaffected by React state)
- The account page still renders the old `backendUser` data (component is still mounted)
- There is no navigation away from `/account`

**Root cause:** React state change alone does not clear wagmi, Openfort SDK, or browser cookie state.

**Fix:** after `deleteAccount()` succeeds, call `window.location.replace('/')` — a hard redirect
that destroys the entire React tree, wagmi connection state, Openfort SDK state, and all local
storage in one shot.

### P2 — Confirmation modal too weak

The original modal had one text paragraph and a single Confirm button. User could confirm by
accident with one click.

**Fix:** redesign modal with two explicit checkboxes — both must be ticked before the Confirm
button is enabled.

---

## Requirements

1. Clicking **Delete My Account** opens a modal styled with a red border
2. Modal shows a permanent-action warning
3. Two checkboxes (both required):
   - "My embedded Openfort wallet will be permanently deleted"
   - "My InfraFund account and all associated data will be permanently deleted"
4. **Confirm Delete** button is disabled until both checkboxes are ticked
5. While deleting: button shows "Deleting…" and is disabled; checkboxes are disabled
6. On error: red error message shown in modal; checkboxes remain ticked; user can retry
7. On success: hard redirect to `/` via `window.location.replace('/')`
8. Closing the modal resets both checkboxes
