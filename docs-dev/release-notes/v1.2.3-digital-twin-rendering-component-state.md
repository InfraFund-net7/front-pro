# v1.2.3 — Digital Twin Rendering Component State

## Summary

This release proves component-level visibility control for the digital twin renderer using a componentized wind turbine glTF model. The `/projects/3/digital-twin` test page now maps construction milestones directly to stable glTF component IDs so selected milestones show their matching model components and unselected milestones hide them.

## Highlights

- Added a componentized `Wind_Turbine_3.gltf` model with stable node IDs for tower, access platform, nacelle/hub, and individual blades.
- Updated the project 3 digital twin page to use the new model and milestone-to-component mappings.
- Improved viewer visibility logic so nested glTF component nodes can be resolved by their own name or parent names.
- Prevented hidden model components from continuing to cast or receive shadows.
- Documented the completed hardwired milestone/component concept test and the next database-backed milestone mapping phase.

## Validation

- Confirmed the new public glTF asset references its copied binary buffer correctly.
- Confirmed all six expected component node IDs exist in the public model.
- Ran `npm run format:lint` successfully.
