for auth and web3 embedded wallet support , with in the process we have to make a detour for new 
users with a questionaire and only register and create a wallet for them if they qualify. 
 
I had implemented openfort for auth and embeddded wallet support with a Go backend, the openfort 
login/registration worked as expected, see `docs-dev/release-notes/v0.2.*.md` , so mainly like : 
 
1. User clicks the Openfort button → authenticates (Google, Email OTP, etc.).
2. No wallet is created (`connectOnLogin: false`, `embeddedState` stays at `EMBEDDED_SIGNER_NOT_CONFIGURED`).
3. Frontend calls the backend with the Openfort access token to check if the user already exists.
4. **Existing user** → backend session exchange → enter the app.
5. **New user** → qualification questionnaire → if qualified, exchange with role/type → create wallet → enter the app. 
 
as described in @docs-dev/release-notes/v0.2.2-openfort-implementation-with-onboarding.md
